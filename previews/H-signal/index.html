// 01 · SCORING

#score

How the score works

No black box. Every point is traceable to a line in your résumé.

Parse fidelity
94%

How much of your PDF the parser can actually read: text layer, reading order, and headings intact. A scanned image scores zero no matter how good it looks.

Keyword coverage
69%

The share of the posting's required skills that appear verbatim in your résumé, weighted by how often the posting repeats each one.

Formatting risk
12%

Layout choices that break parsers — tables, columns, icons, text baked into images. Lower is better; this draft is nearly clean.

Seniority match
81%

Whether the years and scope you claim line up with the level the posting is hiring for, title by title.

// 04 · LOCAL-FIRST

#local

Runs locally

no network calls · no account · localStorage only

Your résumé never leaves the tab it was typed in. Parsing, matching, and scoring all run in the browser against files you pick yourself; the only thing persisted is your own draft, in this browser's localStorage. There is no account to create, no upload to wait for, and no analytics script watching which template you click.

no telemetry

// 05 · POWER-USER TOOLING

#agent

Optional agent

For people who want the loop closed. The agent is a local Playwright job you run yourself: it opens a posting, reads it, and drafts tailored bullets against your own résumé — then hands them back for you to edit. AI providers are opt-in and bring-your-own-key; with none configured, the matcher and the formatter still run fully offline.
